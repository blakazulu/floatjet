## 📖 How to Use This System

### For Creating a New Task

1. Copy [`task-template.md`](./task-template.md)
2. Assign unique task ID (next available FJ-XXX number)
3. Fill in all frontmatter fields
4. Add detailed subtasks and acceptance criteria
5. Save to appropriate folder (month/week or category)
6. Update relevant overview files
7. Update this dashboard

### For Updating Task Progress

1. Open the task file
2. Check off completed subtasks (`- [x]`)
3. Add entry to progress log with date and hours
4. Update `actual_hours` in frontmatter
5. Change `status` if needed
6. Document any blockers or issues
7. Commit changes to Git

### For Completing a Task

1. Verify all acceptance criteria are met
2. Update `status` to `"completed"`
3. Fill in final `actual_hours`
4. Add completion note to progress log
5. Move file to `completed/YYYY-MM/` folder
6. Update week overview file
7. Update this dashboard
8. Update category view file

### Weekly Review Process

**Every Friday:**

1. Review week overview - what got done?
2. Update all task statuses
3. Identify and document blockers
4. Calculate velocity (tasks completed)
5. Plan next week's priorities
6. Update this dashboard
7. Commit all changes to Git

### Monthly Review Process

**Last day of each month:**

1. Review month objectives - were they met?
2. Calculate actual vs estimated hours
3. Analyze velocity trends
4. Document lessons learned
5. Plan next month's focus
6. Archive completed tasks
7. Update master plan if needed

## 🔧 System Conventions

### Task ID Format

- **Pattern:** `FJ-XXX` (FloatJet + sequential number)
- **Examples:** FJ-001, FJ-002, FJ-123
- **Never reuse IDs** - even for deleted tasks

### Status Values

| Status        | Meaning                          | Symbol |
|---------------|----------------------------------|--------|
| `not-started` | Task not yet begun               | ⏳      |
| `in-progress` | Actively working on it           | 🚧     |
| `blocked`     | Cannot proceed due to dependency | 🚫     |
| `review`      | Work complete, needs review      | 👀     |
| `completed`   | Done and verified                | ✅      |
| `archived`    | Moved to completed folder        | 📦     |

### Priority Levels

| Priority | Definition | Use Case                         |
|----------|------------|----------------------------------|
| `P0`     | Critical   | Must have for MVP/launch         |
| `P1`     | High       | Important for success            |
| `P2`     | Medium     | Should have, but not critical    |
| `P3`     | Low        | Nice to have, future enhancement |

### Category Tags

- **Technical:** Infrastructure, development, deployment
- **Content:** Writing, editing, publishing articles
- **SEO:** Optimization, keywords, schema markup
- **Affiliates:** Program management, link placement
- **Design:** UI/UX, mockups, visual assets
- **Analytics:** Tracking setup, data analysis
- **Marketing:** Promotion, outreach, social media

### File Naming Conventions

- **Format:** `task-###-brief-description.md`
- **Examples:**
    - `task-001-astro-setup.md`
    - `task-006-money-page-project-management.md`
    - `task-015-google-search-console.md`
- **Use lowercase with hyphens**
- **Keep description concise** (3-5 words max)

## 🎓 Tips for Success

### Task Writing Best Practices

1. **Be specific:** "Write homepage copy" → "Write homepage hero section (150 words) with 2 CTAs"
2. **Make measurable:** "Improve performance" → "Reduce page load time to <2 seconds"
3. **Include context:** Link to relevant docs, PRD sections, design files
4. **Break down complexity:** If >8 hours, split into multiple tasks
5. **Document dependencies:** Note what blocks this task and what it blocks

### Progress Tracking Tips

1. **Update daily:** Even small progress keeps momentum
2. **Log hours honestly:** Helps with future estimation
3. **Note blockers immediately:** Don't let them linger undocumented
4. **Celebrate wins:** Check off those subtasks!
5. **Review weekly:** Catch drift early

### Avoiding Common Pitfalls

1. ❌ **Don't:** Create vague tasks like "Build website"
   ✅ **Do:** "Create homepage component with hero, features, CTA"

2. ❌ **Don't:** Skip acceptance criteria
   ✅ **Do:** Define clear "done" conditions

3. ❌ **Don't:** Let task list get stale
   ✅ **Do:** Weekly reviews to keep current

4. ❌ **Don't:** Work on blocked tasks
   ✅ **Do:** Resolve blockers first or find workarounds

5. ❌ **Don't:** Create tasks without estimates
   ✅ **Do:** Estimate hours (even if rough)
